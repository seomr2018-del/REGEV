# איפיון מוצר — לוח לידים (Leads Dashboard)

> מסמך זה מתעד את האיפיון המלא של "לוח לידים" כפי שמומש בפועל ב-Artifact שפורסם
> (`https://claude.ai/artifact/6T5KrGmL4962AhFHAVpfhD`), ומשמש כמקור אמת (source of
> truth) לתחזוקה ולפיתוח עתידי של הדשבורד. עותק סטטי של הדשבורד נשמר בתיקייה
> `dashboard/index.html` בשורש הריפו, וקובץ ה-spec המכונה-קריא הנלווה נמצא ב-
> `docs/leads-dashboard/dashboard.spec.json`.

## 1. מטרת המוצר

דשבורד ניהול לידים חד-עמודי (single-page) המרכז את כל הלידים שמגיעים מקמפיין
מכירה של "חנות אונליין", ומאפשר לנציג המכירות:

1. לקבל תמונת מצב מיידית על מצב הלידים (כמה פעילים, כמה נסגרו, כמה חמים, כמה לא
   מגיבים).
2. לאתר ולתעדף לידים "חמים" שדורשים טיפול מיידי.
3. לסנן, לחפש ולמיין את רשימת הלידים המלאה.
4. לגשת במהירות לנוסחי הודעות וואטסאפ מוכנים לפי סוג הליד, ולתסריט הבוט
   האוטומטי.

## 2. משתמשים

- **נציג/ת מכירות** — המשתמש העיקרי; עובד/ת מול הדשבורד מדי יום, מסנן לפי שלב,
  מעתיק מספרי טלפון והודעות.
- **מנהל/ת** — צופה בסקירה הכללית (KPIs, משפך, תובנות) לצורך מעקב ביצועים.

## 3. מבנה המסך

הדשבורד בנוי כעמוד יחיד (`index.html`), RTL, בעברית, עם ניווט לפי `#hash` בין 3
טאבים. כל טאב הוא `<section>` שמוסתר/מוצג לפי הכתובת הנוכחית (`location.hash`).

### 3.0 מבנה כללי (Header)

- **Header דביק** (`position: sticky`) עם רקע מטושטש (`backdrop-filter: blur`).
- לוגו + שם "לוח לידים".
- ניווט טאבים: **סקירה** / **לידים** / **הודעות**.
- שדה חיפוש גלובלי (שם / טלפון / הערה) — מסנן ומוביל אוטומטית לטאב "לידים".
- כפתור החלפת ערכת נושא (בהיר/כהה), עם שמירת העדפה ב-`localStorage`
  (מפתח `leads-theme`).

### 3.1 טאב "סקירה" (Overview)

| רכיב | תיאור |
|---|---|
| **כותרת עמוד** | "סקירת לידים" + תת-כותרת + חותמת (`stamp`) המציגה סה"כ מספר לידים |
| **כרטיסי KPI** (4) | ראו סעיף 4 |
| **משפך לידים (Pipeline)** | פס אחד מחולק ל-5 מקטעים לפי שלב (יחסי לגודל כל קבוצה); לחיצה על מקטע/legend מסננת את טאב "לידים" לפי אותו שלב ומנווטת אליו |
| **פילוח לפי סטטוס** | Bar chart אופקי לכל סטטוס מפורט (לא שלב מקובץ), ממוין מהגדול לקטן |
| **חמים לסגירה** | רשימת לידים עם `hot=true` (ראו סעיף 5.2) שטרם נסגרו |
| **עומק המעקב** | היסטוגרמת עמודות (0–3) — כמה "נגיעות" (`touch`) תועדו לכל ליד |
| **שווה לבדוק (Insights)** | 4 תובנות מחושבות אוטומטית מהנתונים (ראו סעיף 6) |

### 3.2 טאב "לידים" (Leads)

| רכיב | תיאור |
|---|---|
| **מונה תוצאות** | "מוצגים X מתוך N" |
| **שבבי סינון (chips)** | הכל + 5 שלבים + "חמים בלבד"; לחיצה חוזרת על שבב פעיל מבטלת את הסינון |
| **מיון** | `select` עם 4 אפשרויות: לפי שלב (ברירת מחדל), לפי שם, הכי הרבה נגיעות, סדר הגיליון המקורי |
| **טבלת לידים** | עמודות: שם, נייד (+ כפתור העתקה), סטטוס (pill צבעוני), ניסיון ראשון, ניסיון שני, עדכון אחרון, הערות/תשלום |
| **תגיות שורה** | `חם` (כתום) כשה-ליד "חם"; `כפול` כשה-ליד מזוהה כשכפול (מספר טלפון חוזר); `שולם` (ירוק) בעמודת ההערות כשזוהה תשלום |
| **תצוגת מובייל** | מתחת ל-768px הטבלה הופכת לכרטיסים (כל שורה = כרטיס, כותרות עמודה כ-`data-label`) |
| **ריק** | הודעת "לא נמצאו לידים..." כשאין תוצאות תואמות לסינון/חיפוש |

### 3.3 טאב "הודעות" (Messages)

| רכיב | תיאור |
|---|---|
| **תבניות הודעה** | כרטיס לכל סוג ליד (`type`), עם מטרה (`goal`) ועד 3 "בועות" הודעה (שלב א׳/שלב ב׳/הודעה נוספת), כל בועה עם כפתור העתקה |
| **תסריט בוט חכם** | רשימה מסודרת (timeline) של שלבי שיחה אוטומטיים — שאלה (`q`) ותשובה/הנחיה נלווית (`a`) |

## 4. כרטיסי KPI (טאב סקירה)

מחושבים על כלל מאגר הלידים (`N` = סה"כ שורות):

| KPI | נוסחה | תת-כיתוב |
|---|---|---|
| לידים פעילים | `N - closed - idle` | "מתוך N לידים בגיליון" |
| נסגרו | `count(stage=done)` | "X% המרה · Y מסומנים \"שולם\"" |
| חמים לסגירה | `count(hot=true)` | "סומנו \"חם\" או \"לסגור\" בעדכון" |
| לא מגיבים | `count(stage=block)` | "X% מהלידים" |

## 5. מודל נתונים

### 5.1 שורת ליד גולמית (כפי שמגיעה מהגיליון)

| שדה | תיאור |
|---|---|
| `p` | מספר טלפון, מפורמט לתצוגה (LTR) |
| `k` | אותו מספר טלפון, ספרות בלבד — משמש כמפתח לזיהוי כפילויות |
| `n` | שם הליד (יכול להיות ריק) |
| `a1` | תיעוד ניסיון יצירת קשר ראשון |
| `a2` | תיעוד ניסיון יצירת קשר שני |
| `u` | עדכון אחרון (חופשי) |
| `s` | סטטוס מפורט — אחד מרשימת הסטטוסים הסגורה (סעיף 5.3) |
| `x` | הערות / מידע על תשלום |
| `dup` | `true`/`false` — הליד מזוהה כשכפול של שורה אחרת (טלפון זהה) |

### 5.2 שדות מחושבים (בזמן טעינה, לכל שורה)

| שדה | חישוב |
|---|---|
| `g` | אובייקט השלב (Stage) שאליו משתייך הסטטוס `s`, לפי מיפוי סעיף 5.3 |
| `hot` | `true` אם `u` מכיל את המחרוזת "חם" או "לסגור" **וגם** `g.id != 'done'` |
| `paid` | `true` אם `x` מכיל את המחרוזת "שולם" |
| `touch` | מספר השדות הלא-ריקים מתוך `[a1, a2, u]` (0–3) |

### 5.3 שלבים (Stages) ומיפוי סטטוסים

הדשבורד מקבץ את הסטטוסים המפורטים (חופשיים, מהגיליון) ל-5 שלבים קבועים, כל
אחד עם צבע ייעודי:

| מזהה שלב | תווית | צבע | סטטוסים משויכים |
|---|---|---|---|
| `done` | נסגר | ירוק אמרלד (`--done`) | `נסגר` |
| `prog` | בטיפול חם | כתום ענבר (`--prog`) | `נשלחה הודעת לחץ`, `מתלבט עדיין \מתייעץ`, `מעוניין תומר לחזור אליו`, `קבע \ רוצה שיחה` |
| `pend` | ממתין לתגובה | תכלת שמיים (`--pend`) | `נשלחה הודעה לתיאום שיחה`, `נשלחה הקלטה \ מלל`, `רוצה לחכות` |
| `block` | לא מגיב | אדום ורד (`--block`) | `לא מגיב!` |
| `idle` | ירד מהפרק | אפור (`--idle`) | `לא מעוניין`, `לא רלוונטי`, `לקוח שאני לא רוצה להכניס` |

סטטוס שאינו מופיע באף רשימה נופל כברירת מחדל לשלב `idle`.

### 5.4 מודל תבנית הודעה (טאב הודעות)

| שדה | תיאור |
|---|---|
| `type` | שם סוג הליד (למשל "מתעניין כללי", "קר"...) |
| `goal` | מטרת ההודעה עבור סוג ליד זה |
| `m1`, `m2`, `m3` | עד 3 נוסחי הודעה (שלב א׳ / שלב ב׳ / הודעה נוספת); שדה ריק לא מוצג |

### 5.5 מודל שלב בתסריט הבוט

| שדה | תיאור |
|---|---|
| `q` | תוכן השלב / השאלה שהבוט שולח |
| `a` | התגובה/הענף הבא בתסריט (אופציונלי) |

## 6. תובנות אוטומטיות (Insights)

מחושבות בזמן טעינה על בסיס הנתונים, ללא קלט משתמש:

1. **לידים סגורים בלי "שולם"** — `count(g.id=done AND paid=false)`.
2. **לידים עם נגיעה אחת בלבד** — `count(s == "נשלחה הודעה לתיאום שיחה" AND touch <= 1)`.
3. **מספרים כפולים** — מספר הערכים הייחודיים של `k` שמסומנים `dup=true`.
4. **לידים בלי שם** — `count(n == "")`.

## 7. אינטראקציות ופונקציונליות חוצות-מסך

- **חיפוש**: מסנן חופשי לפי שם/הערות/סטטוס וכן לפי ספרות טלפון (3+ ספרות
  רצופות); מתעדכן על כל הקלדה; מנווט אוטומטית לטאב "לידים" עם הקלדה ראשונה.
- **סינון לפי שלב**: ניתן דרך משפך הלידים (סקירה) או שבבי הסינון (לידים);
  מצב הסינון (`sel`) משותף בין שני המסכים.
- **מיון**: 4 מצבים — לפי שלב (סדר קבוע), לפי שם (א'-ב', ריקים בסוף), לפי
  מספר נגיעות (יורד), לפי סדר מקורי בגיליון.
- **העתקה ללוח**: בכל מספר טלפון ובכל נוסח הודעה — כפתור העתקה עם
  `navigator.clipboard`, ו-fallback ל-`document.execCommand('copy')`;
  הודעת Toast "הועתק" לאחר הצלחה.
- **Tooltip מותאם**: מופיע במעבר עכבר מעל אלמנטים עם `data-tip` (מקטעי
  משפך, שורות בר, עמודות היסטוגרמה).
- **החלפת ערכת נושא**: בהיר/כהה, נשמר ב-`localStorage`, ברירת מחדל לפי
  העדפת המערכת (`prefers-color-scheme`).
- **נגישות**: `aria-current` לטאב פעיל, `aria-pressed` לשבבי סינון,
  `aria-label` לכפתורי אייקון, מחלקת `.sr` להסתרה חזותית בלבד, כיבוד
  `prefers-reduced-motion`.

## 9. דרישות לא-פונקציונליות

- עמוד HTML עצמאי אחד (ללא תלות שרת), הנתונים מוטמעים כ-`<script type="application/json">`.
- תמיכה מלאה ב-RTL ובעברית (`dir="rtl" lang="he"`), גופן Rubik מ-Google Fonts.
- תמיכה בהתקן נייד (safe-area insets, `viewport-fit=cover`).
- ללא שמירה חיצונית — כל מצב (סינון/מיון/ערכת נושא) הוא Client-side בלבד;
  ערכת הנושא היחידה שנשמרת בין ביקורים היא בזיכרון הדפדפן (`localStorage`).
